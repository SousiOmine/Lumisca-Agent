# Web スタイル構成

`../styles.css` をエントリーポイントとし、実際のスタイルは本ディレクトリの個別ファイル群で管理しています。MDN の「CSS の整理」の指針に沿った構成です。

- 単一の大きなスタイルシートではなく、全体共通ルールと各画面・コンポーネントごとのシートに分割しています。
- カスケードの優先順位は、`styles.css` における `@import` の記述順に従います。

## デザイン言語

形は「余白のある土台（canvas）と、その上に浮く面（surface）」の 2 層と、大きめの角丸で作ります。色相は使わず、無彩色のランプだけで段差と状態を示します。

- **面の描き方**: 作業面（チャット、ダイアログ、カード）は `--surface`・`1px solid var(--border)`・`--shadow-panel` で描きます。土台との差は「色の差」ではなく「浮き」で作るため、影は広く低く、枠は髪の毛ほどの濃さに留めます。
- **色のランプ**: `--surface` → `--surface-2` → `--surface-3` は必ず暗くなる方向に並べます。面の内側に置く行や井戸（一覧、ログ）はこの段を使い、`--bg`（canvas）を内側に使うと面に穴が空いて見えます。
- **角丸**: 下表の段だけを使い、ピクセル値を直接書きません（`styles_test.ts` が検証します）。
- **状態**: 選択中の行は `--surface-3` と文字の太さで示します。色相のアクセントは持たないため、`6%` 程度の淡い塗り（`--accent-soft`）だけでは選択が読めません。
- **フォーカス**: 枠は `--border-strong` まで一段深くし、外側に `--accent-soft` のリングを足します（入力欄・コンポーザ）。

### 角丸の段

| トークン | 値 | 用途 |
|---|---|---|
| `--radius-xs` | 8px | インラインコード、`kbd`、メーターの塗り |
| `--radius-sm` | 12px | 行（メニュー項目、一覧、タブ） |
| `--radius` | 16px | 入力欄、カード、ポップオーバー |
| `--radius-lg` | 22px | ダイアログ、進捗カード、質問カード |
| `--radius-xl` | 26px | コンポーザ、ユーザー発言、チャットと案内の面 |
| `--radius-pill` | 999px | ボタン、タグ、トグル、丸いアイコン |

例外的に許すのは `0`（リセット、全面表示）と `50%`（点、つまみ）だけです。

### 浮いた面の余白

`--app-inset`（既定 12px、`@media (max-width: 600px)` で 0px）が、面と画面端の間の余白です。チャット、stella の各ペイン、通知バナー、そしてタイトルバーのタブと stella の帯がこれを使います（stella の帯は、下の一覧の行の左端に顔を揃えるため、行の内側の余白も足します。ペインや行の余白が変わる幅では、帯もその合計にします）。面を追加するときは、チャットの面の基準位置も同じ計算に合わせてください。

## スタイル追加の手順

1. スタイルを記述するファイルは上記の一覧から選びます。
2. 既存の分類に収まらない場合にのみ新規ファイルを作成し、カスケード順を考慮して `../styles.css` の `@import` に追加してください。
3. 角丸は必ず `tokens.css` の段から選びます。新しい値を足すときは、段とその用途をこの文書と `tokens.css` の両方に書いてください。
4. モーションは下記「モーションの規範」に従います。`reduced-motion.css` への設定は必須で、`styles_test.ts` が漏れを検出します。

## モーションの規範

動きは「何かが起きた」ことを伝えるためのもので、飾りではありません。どの規範も `styles_test.ts` の検査と対になっています。

### 1. 入る時だけ、本当に新しく来たものだけ

- **入場アニメは、要素が DOM に現れたことではなく、利用者の目の前で新しく起きたことに付与します。** 会話の初回描画は読み込み済みの窓を丸ごと描き、遡りは読み手の上へ履歴を差し込みます。ここで無条件にアニメを付けると、会話を開くたびに全件が順に立ち上がり、遡るたびに過去が明滅します。`hooks/useArrivals.ts` が「直前のコミットから末尾に増えた分」だけを返すので、行は `data-enter` を付けて描き、CSS は `.stella-msg[data-enter]` のように**ゲート付きで**アニメを書きます。
- **ストリーミング中の本文が確定しただけの行は入場ではありません。** 同じ語が跳ね返るので、`withoutHandoff` で除外します。
- **一度きりで条件付きにマウントされる面**（ダイアログ、カード、ペイン）は、そのまま `animation` を書いて構いません。並ばないので再描画のたびに走ることはありません。stella の会話シートの右からの入場（`lum-enter-right`）も同じ扱いです——`data-screen="conversation"` になったときに 1 度だけ走り、会話を切り替えても表示が変わらないので再走しません。その代わり、会話の URL を直接開いた初回描画でも走ります（ダイアログの入場と同じで、面がそこに現れること自体が入場だからです）。

### 2. 退出は、残すと決めた面だけ

消える要素は即座に消します。**モーダル**、**仮想マシンの画面ペイン**、**画像の拡大表示（`components/Lightbox.tsx`）**だけは、`hooks/usePresence.ts` でマウントを保ったまま退出を再生します（消える先が空間的に連続しないため）。退出の再生は `motion.ts`（`motion/mini` を遅延読み込みする唯一の入口）に限ります。

拡大表示の開く・閉じるは、中央で 0.96 倍 ⇄ 等倍の拡大とフェードです。入場は CSS（`.lightbox` と `.lightbox-image`）、退出は `play()` で、拡大したまま閉じたときは現在の `transform` から縮み始めます。

### 3. 曲線は用途で選ぶ（`tokens.css`）

| トークン | 用途 |
|---|---|
| `--lum-ease-out` | 入場・退出。最初のフレームから動く（`ease-in` は UI では使わない） |
| `--lum-ease-in-out` | 画面上で移動・変形するもの（インジケータの移動、塗りの伸長） |
| `--lum-ease-drawer` | 端から入ってくるペイン |

時間は `--lum-dur-fast`（120ms）/ `--lum-dur-mid`（180ms）/ `--lum-dur-slow`（240ms）から選びます。UI のアニメは 300ms 未満に収めます。

### 4. 動かすのは `opacity` と `transform` だけ

レイアウトとペイントを飛ばすこの 2 つだけです。**寸法（`width` / `height`）は動かしません**。仮想マシンの画面は noVNC がボックスからスケールを引き直すため、寸法が動くと毎フレーム絵が拡縮します（`styles_test.ts` が canvas の寸法指定を禁じています）。

唯一の例外は**折りたたみ（`.collapse`）の `grid-template-rows: 0fr ⇄ 1fr`** です（`motion.css`）。開く面は「中身の高さ」という値を持たないため、`transform` では表せません。測った高さを `height` に書くと、ストリーミングで伸びる中身に対して次のフレームには古くなります。`1fr` はブラウザが中身から答え続けるので、伸び縮みする本文にも追従します。`width` は今までどおり禁止です（noVNC の制約）。

**拡大表示の拡大縮小も `transform` です**（`lightbox-zoom.ts`）。画像の寸法は書き換えず、`translate3d(...) scale(...)` を要素へ直接書きます。ホイール・ピンチ・ドラッグは連続した入力なので、`transition` はクリックで倍率が飛ぶときだけ付けます（`data-zoom-smooth`）。

**`transform` を使えない場所が 1 つあります**: stella の一覧が、会話を開いたときの中央から左端への移動です（`stella.css` の `.stella-sidebar` の `left`）。`transform` は要素を包含ブロックにするので、一覧の中の `position: fixed`——行の ⋮ メニューと、エージェントの作成・編集・削除のダイアログ——がウィンドウではなく一覧の箱（`--stella-list-width`）を基準に置かれて壊れます。`left` は相対配置の長さで、2 つの状態（`0` と中央寄せの `calc()`）の間を補間でき、要素 1 つ分の再配置しか起こしません。一覧は誰も選ばれていない間ほど広い幅（`--stella-list-width-alone`）を取りますが、幅そのものは遷移させません——移動は `left` の補間だけが担い、幅は最初のフレームから行き先の値です。仮想マシンの画面が開くときの `flex-basis` の受け渡し（`.stella-main`）と同じ種類の、意図した例外です。

### 5. `transition` はプロパティを名指しし、トークンを読む

`transition: all` は誰も選んでいないプロパティまで追跡します。リテラルの時間・イージング（`120ms ease`）はトークンの代わりに別系統を作ります。両方とも `styles_test.ts` が検出します。

### 6. ループする動きは reduced-motion で止める

`prefers-reduced-motion: reduce` では「減らす」のであって「0 にする」のではありません。**フェードは残し、移動・拡大・回転と自走するループは落とします。** 入場は `lum-fade-only` に置き換え、矢印の回転など移動のみの `transition` は `none` にします。追加したアニメは必ず `reduced-motion.css` に登録してください（`styles_test.ts` が全シートを照合します）。

### 7. 画面遷移は階層のある移動だけ

画面がまるごと入れ替わる移動のうち、**階層を下る・戻るもの**だけが遷移します。対象は stella のエージェント一覧 ⇄ 会話と、設定のカテゴリ一覧 ⇄ カテゴリページで、判定は `../screen-transition.ts` の `screenMove` がアドレスの組から決めます。タブの切り替え、新規セッション画面とセッション、ダイアログの開閉は対象外です（並列の面の切り替えであり、階層ではないためです）。

- **向きは `data-vt`、速さと形は CSS**: 移動の向きは JS が `<html data-vt="push|back">` として書き、規則はそれを読みます。遷移が終わると属性は消えるので、走っていない遷移の規則が選ばれることはありません。
- **内側の要素に `view-transition-name` を書かない**: 名前を持つ要素は別スナップショットになり、同時に包含ブロックになります。`position: fixed` の面（ダイアログ、仮想マシンの画面）が、自分自身ではなくその要素を基準に置かれて壊れます。スナップショットはページ全体で 1 枚です。
- **幅で形を変える**: 600px 以下は横スライド、それ以上はクロスフェードです。画面いっぱいの列が横に動くのは、隣が最初から横にあった広い画面では過剰なためです。
- **2 列の stella は遷移しない**: 広い画面では一覧と会話が同時に並び、エージェントを選ぶと一覧そのものと会話シートがレイアウトの側で動きます（`stella.css`）。ページ全体のスナップショットを取ると、中央にあった一覧と左へ動いた一覧の 2 枚が写って二重にフェードします。`screenMove` は `ScreenLayout.singleScreen`（= 900px 以下）が偽なら stella の移動を遷移にしません。設定の一覧 ⇄ カテゴリは、ページが隣に残るので幅に関係なくクロスフェードです。
- **`--vt-in` / `--vt-out` はトークン**: 向きごとの移動量は `tokens.css` が宣言し、`html[data-vt]` の 2 ブロックが値を与えます。キーフレームが方向ごとに増えないので、reduced-motion の上書き先も 1 対のままです。
- **reduced-motion ではフェードに落とす**: 遷移は構造上すべて移動なので、`reduced-motion.css` が同じ 1 対をフェードのキーフレームへ差し替えます。

## レスポンシブ設計

画面幅の条件は 2 つ、入力デバイス（タッチ）の条件は 1 つです。これらは `tokens.css` の先頭で定義されており、`styles_test.ts` で検証されます。

| 条件 | 分類 | 適用内容 |
|---|---|---|
| `@media (max-width: 900px)` | compact | 余白の削減、折り返しの許可、固定幅の解除 |
| `@media (max-width: 600px)` | phone | 1 カラム表示、全面表示のモーダルと面、進捗の行の高さ上限を切り詰め、`--app-inset: 0px`、文字を 1 段とボタン・行のタップ領域を控えめに拡大 |
| `@media (hover: none), (pointer: coarse)` | touch | ホバー前提の操作の常時表示、タップ領域の拡大、入力欄を 16px 以上に設定 |

- **メディアクエリの記述位置**: 上書きルールは該当コンポーネントのシート末尾に記述します。シート単位でカスケードされるため、同じシート内の通常ルールより優先されます。他のシートのルールを別シートから上書きすることは避けてください。
- **phone と touch は役割が違う**: phone は「狭い画面をどう読むか」、touch は「指でどう触るか」です。両方に当たる端末（スマホ）では特異度が同じなので、**後に書いたほうが勝ちます**。phone の拡大ルールは各シートの touch ブロックより後ろに置いてください（`styles_test.ts` が順序を検査します）。phone ブロックが先頭にあるシートでは、レイアウトを組み替えるブロックと、文字とタップ領域を拡大するブロックを分け、後者を末尾に置きます。
- **高さの指定**: `vh` はブラウザの UI やソフトウェアキーボードの変化に対応できないため、画面に合わせる要素（モーダルやパネルなど）には `dvh` を使用します。アプリ全体の高さは `--app-height`（既定値 `100dvh`）とし、タッチ端末では `hooks/useAppHeight.ts` が `visualViewport` の高さを反映します。
- **動的な値の受け渡し**: キャレット位置（`--caret-x`, `--caret-y`）やダイアログの幅（`--modal-width`）など、場所に応じて動的に変わる値はインライン style で直接指定せず、CSS 変数として渡してください。
- **トリガーにぶら下がるポップオーバー**: `bottom: 100%` のような固定の相対配置は書かないでください。ウィンドウが低いと画面外へ出て、`overflow: hidden` の面の中では切れます。モデルピッカーは `hooks/usePopoverPlacement.ts` がトリガーの矩形と `visualViewport` から位置・幅・高さを測り、`--mp-*`（`tokens.css`）として渡します。ポップオーバー自体は body への portal に置き、`.mp-popover` を使ってください。幅が足りない・高さが足りない場合の「1画面ずつ」への切り替えも同じ計測結果で決めます（メディアクエリでは判定できません）。

## ビルド時の留意事項

- 開発環境（Vite）では、Vite が `@import` を解決します。
- 本番・パッケージ版では、サーバー（`packages/server/assets.ts`）が `styles.css` の `@import` を同一順序でインライン展開して配信します。そのため、`styles/` ディレクトリ外への `@import` や URL 形式の参照は使用しないでください。
